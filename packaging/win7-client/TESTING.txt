Horizon Direct3D9 preview - Windows 7 SP1 x64

This preview requires the GPU manufacturer's Windows 7 driver, prepared legal
Horizon resources matching Minecraft 26.3, and an Atom N455-compatible x64 CPU
(SSE3/SSSE3). The owner reports the HAL smoke test works on GMA3150. Gameplay on that GPU and
on Radeon HD4570 is not verified. The owner reports the preceding RTX3050 build
reached about 400 FPS at 16 chunks (700+ with F1); camera stalls disappeared.
This update needs another RTX3050 retest before moving back to target hardware.
No Java, Vulkan, OpenGL, D3D11/D3D12 or shader compiler is used by the DX9 renderer.

1. Extract the entire ZIP. In the existing legacy launcher select horizon-client.exe as the native client.
   Use your existing prepared resources. DX9 is the default for this executable.
   Direct launch, if needed:
   horizon-client.exe --control --resources "C:\path\to\26.3" --game-dir "C:\path\to\test-game"
   Test in a COPY of a save. Render distance, FPS, resolution and vanilla graphics
   options stay under your control; no low preset is installed.
2. Open a world, move around, open inventory/chat, type/copy/paste Unicode text, save/reopen the world,
   resize, Alt+Tab and toggle fullscreen. F2 saves a screenshot. Send the client log
   and crash report (if any), GPU driver version and the build-info.txt from this ZIP.
   The log includes adapter caps, HAL/vertex mode, memory budgets, frame CPU/Present,
   draw calls, texture states and upload bytes. Counters are not a hardware benchmark.
   Compare the same view at 16 chunks with HUD on/off (F1), player view (F5),
   inventory item depth and environmental fog. Try F3+A and let the rebuild settle.

Performance diagnosis (no profiler installation needed):
The normal log and F3 now separate lightmap, sprite animation, GUI patches,
visibility, terrain cache, solid/translucent draws, entities, effects/hand and GUI.
These are CPU elapsed times (including driver waits), not GPU timestamp queries.
The five-second log reports compressed CPU geometry and its decoded size, static
DEFAULT GPU arenas, stream/index/mesh upload bytes, interval average/peak CPU time
and stages of the worst frame, texture bytes and process memory [private resident estimate, resident, total RAM].
The GUI log separates its draw calls, texture binds, vertex upload bytes and buffer
locks. Used virtual atlas tiles share physical pages; an ordinary HUD uploads
once and draws through ordered ranges. Oversized batches still draw in pieces.
Remove the old HORIZON_D3D9_MESH_MIB / HORIZON_D3D9_TEXTURE_MIB overrides to test
automatic targets. For the RTX3050 retest use the same world/settings as before. Let chunks and compaction settle,
then send latest.log, a screenshot of F3, and these optional local reports from a
second terminal while the world runs. IMPORTANT: start the game with --control
(pass it to horizon-client.exe, as in the direct command above). If your launcher
exposes game arguments, append --control there; the minimal Win7 launcher may not.
Without --control the tool only returns a connection error, not a memory/FPS report.
The local control endpoint is not silently enabled by this build:

  horizon-ctl.exe bench 20 > frame-stats.json
  horizon-ctl.exe memory > memory.json
  horizon-ctl.exe trace render-trace.json 10
The last command records existing Horizon CPU spans for a browser trace viewer.
If the launcher uses a custom HORIZON_HOME, set that same home in this terminal.

Memory targets now manage caching, rather than aborting at 128 MiB. Native-sized
sprite pages and small isolated animation/GUI pages avoid the old giant atlas.
CPU geometry uses lossless delta/byte-plane compression. Immutable regional DEFAULT arenas share
vertices across sections. The existing CPU portal/column culling rejects hidden
sections. Hardware vertex processing batches solid terrain by texture using retained
visibility indices; unchanged ranges do not upload each frame. One bounded CPU
worker preloads reachable shadows and compacts small VBs into larger pages, keeping
old data until upload succeeds. Changed meshes use the existing expanded vertices
for eager GPU upload, including behind the camera when budget allows. The log's
eager_sections and compactions are cumulative successful-operation counts.
Software vertex processing keeps narrow direct
draw ranges to avoid transforming sparse arena spans. Offscreen GPU buffers are
evicted first. Automatic cache targets now scale beyond 128 MiB when the adapter
and system RAM allow it. Dynamic vertex/index streams append with NOOVERWRITE and
DISCARD only at wrap; uncached geometry remains drawable. GUI batching only reorders
screen bounds that cannot overlap. Resize now replaces only the presentation/depth
surfaces; look for "terrain buffers preserved", without a mesh-cache collapse. A
real lost-device Reset still rebuilds DEFAULT data. Embedded ps_2_0 fog combines the
spherical environmental and cylindrical distance curves, with no vertex shader or
compiler requirement. The log names any fixed-function approximation fallback.
The sky has a horizon gradient. Shared mip generation preserves fast-leaf colours.
Texture Filtering=None keeps nearest mip transitions; the existing nonzero filtering
choices use linear/trilinear filtering when supported (RGSS/anisotropy are approximated). User
render distance and texture quality are not rewritten. The Video Settings API
row explicitly shows Direct3D 9; this Win7 executable offers DX9 only.

Optional diagnostic overrides (normally unnecessary; no options files edited):
HORIZON_D3D9_VERTEX_PROCESSING=software   (A/B fixed-function vertex processing)
HORIZON_D3D9_VERTEX_PROCESSING=hardware   (only when caps expose hardware T&L)
HORIZON_D3D9_MESH_MIB=128                (GPU cache target; excess geometry still draws)
HORIZON_D3D9_TEXTURE_MIB=128             (advisory texture-residency target)

The preview draws CPU-meshed terrain/models, lightmap, transparency, entities,
hand/items, HUD/fonts/chat/inventory, weather, border and screen overlays.
Limitations: SDR, simplified End portal, no fancy clouds/star field, enchantment
foil, shader packs, PBR, post effects, LOD, GPU occlusion/skinning, frame generation
or split-screen compositor. Modern client builds retain their original renderer.
